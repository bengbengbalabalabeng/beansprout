# Beansprout 0.4.0

This release is about two things. You can bring a blog from Jekyll or Hugo and keep its old
links. And readers get more reasons to stay: related posts, a feed per tag and a table of contents
in every theme. It also adds three new themes, a robots.txt and ETags.

It needs Java 25 and Spring Boot 4.1, as before.

## Upgrade

Change the BOM's version:

```xml
<dependency>
    <groupId>dev.danvega</groupId>
    <artifactId>beansprout-bom</artifactId>
    <version>0.4.0</version>
    <type>pom</type>
    <scope>import</scope>
</dependency>
```

With Gradle:

```kotlin
implementation(platform("dev.danvega:beansprout-bom:0.4.0"))
```

If you gave a Beansprout dependency its own version, change that to `0.4.0` too. A version on
the dependency wins over the BOM's. [Use your own templates](../own-templates.md) shows the
starter that way.

Then start the app, open `/blog` and read the log. Beansprout reads the posts on the first
request, so that is when it logs any post it skipped.

## Check these when you upgrade

**A post named with a date gets a shorter address.** A post saved as `2026-03-14-hello.md` with
no `slug:` line used to live at `/blog/2026-03-14-hello`. Now it lives at `/blog/hello`. The old
address answers with a 301 to the new one, so links and search rankings carry over. A post with
its own `slug:` line keeps its address.

The shorter address can make a post disappear. The log names each one it skips:

- Two names that match once the date is gone, like `2023-06-01-weekly.md` and
  `2023-06-08-weekly.md`. Beansprout keeps the first by name and skips the other. A draft or a
  post dated in the future counts too, so it can hide a published post.
- A name that is a blog page once the date is gone: `tags`, `archive` or `page`, as in
  `2026-01-01-tags.md`.
- A name with no Latin letters or digits after the date, like `2026-03-14-こんにちは.md`.

Give each of these a `slug:` line with its old address, like `slug: 2023-06-08-weekly`.

**Keys that used to be ignored are now read.** These are `description`, `image`, `lastmod`,
`canonical`, `canonical_url`, `author`, `aliases`, `redirect_from` and `unlisted`. A post that has
one may now show a summary, a picture or another author's name. Two of them change where a post
appears:

- `unlisted: true` takes the post off the index, tag pages, the archive, the feeds, the sitemap
  and related posts. Its own address still works.
- `canonical` or `canonical_url` takes the post out of the sitemap, and its canonical link points
  at that address.

A post with a bad value is now skipped, with a log line that names it:

- `lastmod` that is not a date.
- `canonical` or `canonical_url` that is not a full `http` or `https` address.
- `unlisted` that is not `true` or `false`.
- `image` with a relative path, like `image: assets/pic.png`. Start it with `/`. A post in its own
  folder may name a picture in that folder, but the file must be there.

**The feed's author is now `beansprout.author`.** It used to be the blog's title. A blog with no
`beansprout.author` keeps the title.

**The app now serves `/robots.txt`.** It allows every path and points to the sitemap. If your app
has its own `robots.txt` in `static/`, or a controller for it, yours answers instead. With a
context path there is none, since crawlers read it only at the root. To turn it off, set
`beansprout.robots.enabled: false`.

**Pages, the feeds, the sitemap and robots.txt now have an ETag** and `Cache-Control: no-cache`.
A 404 or a redirect has neither. A request with a matching
`If-None-Match` gets a 304, and the page is not rendered. If you wrote your own templates and they
show something that is not in `page`, such as a value from your own bean, a reader can keep an old
copy until the app restarts.

**Your own templates don't get the new features by themselves.** The eight themes have them all.
If you wrote your own, these are the new values to render:

- `page.meta.robots`: `noindex` on an unlisted post, as a `<meta name="robots">` tag.
- `page.site.slots`: your own HTML for the head, after each post and in the footer. Don't escape it.
- `page.site.links`: the links from `beansprout.links`.
- `post.related`: posts that share a tag.
- `page.feed` on a tag page: the tag's own feed.
- `post.pictureWidth` and `post.pictureHeight`: the picture's size, empty when unknown.

## Breaking changes for Java code

These only matter if your code builds Beansprout's records or calls `Posts` directly.

- **New record components with no old constructor.** Code that calls these constructors, or
  takes them apart in a record pattern, needs the new values:
  - `content.Post`: `canonical`, `aliases`, `author`, `imageWidth`, `imageHeight`, `unlisted`.
  - `view.Post`: `url`, `pictureWidth`, `pictureHeight`, `related`.
  - `view.Site`: `links`, `slots`.
  - `view.TagPage`: `feed`.
- **New components with the old constructors kept.** `BlogSettings` gains `links` and
  `relatedPosts`. `Meta` gains `robots`. Code that calls their old constructors still compiles.
  A record pattern over them needs the new components.
- **`Posts.published()` leaves out unlisted posts.** The new `Posts.live()` returns every post a
  reader can open, unlisted ones too. `Posts.find()` now finds unlisted posts.
- **`PostSource` gains `open(folder, path)`.** It is a default method that returns null, so a
  source of your own still compiles. Its pictures just get no size.
- **`Pages` gains a constructor that takes `Slots`.** The old one stays and passes no slots.

## New

### Bring your blog with you

- **Jekyll and Hugo posts work as they are.** Beansprout reads `description`, `image`, `lastmod`
  and `canonical_url` as its own keys. It reads Hugo's TOML frontmatter between `+++` lines. A
  Jekyll file name like `2026-03-14-hello.md` gives the post its date.
- **Old addresses redirect.** List them in `aliases` or `redirect_from`, and each one answers with
  a 301 to the post. An alias matches with or without a trailing slash. The static export writes a
  page at each alias that sends the reader on.
- **`canonical`** points a post at the place it first appeared, like dev.to. The post leaves the
  sitemap and stays everywhere else.
- **`author`** shows a post's own writer in place of `beansprout.author`, on the page, in the
  JSON-LD and in the feed.
- **Pictures load faster and don't make the page jump.** Pictures in a post load lazily, except
  the first one when the post has no `picture`. A PNG, JPEG, GIF or WebP in the post's folder gets
  its `width` and `height`.
- **A migration guide**, [Move a blog from Jekyll or Hugo](../migrate.md). It covers the few posts
  you fix by hand.

### Keep readers around

- **Related posts.** After each post, every theme lists up to three posts that share its tags.
  `beansprout.related-posts` sets the number, and `0` turns it off.
- **A feed for each tag**, at `/blog/tags/{tag}/feed.xml`. Each tag page links to it.
- **Unlisted posts.** `unlisted: true` keeps a post off the index, tag pages, the archive, the
  feeds, the sitemap and related posts. Anyone with the address can still read it. Its page tells
  search engines not to index it.
- **A table of contents in five more themes.** Calling Card, Dateline, Linocut, Marginalia and
  Onionskin now show an "On this page" list when a post has `##` headings.
- **Your own HTML on every page.** Put `beansprout/head.html`, `after-post.html` or `footer.html`
  in `src/main/resources/`. Every theme adds it as it is, for analytics, comments or a newsletter
  form. See [Your own HTML on every page](../new-blog.md#your-own-html-on-every-page).
- **Menu links.** `beansprout.links` adds links to every theme's main menu, so a blog inside a
  bigger site links back to the rest of it:

  ```yaml
  beansprout:
    links:
      - label: Shop
        href: /shop
  ```

### Search engines and AI crawlers

- **robots.txt**, with a `Sitemap:` line. Set `beansprout.robots.ai-training: block` to keep AI
  training crawlers out of the blog, while AI search crawlers still read it.
- **ETags and 304s** on pages, the feeds, the sitemap and robots.txt.

See [Search engines and AI crawlers](../search-engines.md).

### Three new themes

Beansprout's own designs. Each follows the reader's light or dark setting and uses system fonts.

| `beansprout.theme` | Artifact | Look |
| --- | --- | --- |
| `plainsong` | `beansprout-theme-plainsong` | A plain list of posts in black and white, no pictures. |
| `onionskin` | `beansprout-theme-onionskin` | Every post typed like a memo, in monospace. |
| `calling-card` | `beansprout-theme-calling-card` | You first: your name in poster-sized type, your photo, your topics. |

### The MCP server and the static export

- The MCP tools `list_posts` and `find_posts_by_tag` leave out unlisted posts. `read_post` reads
  one by its slug.
- The static export now writes robots.txt, each tag's feed, a page at each alias and every
  unlisted post. It puts your slot HTML in every page, as the app serves it.
